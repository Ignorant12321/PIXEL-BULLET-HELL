# 移动端操作与面板优化设计

## 目标

继续优化横屏移动端体验，让战斗操作更像手机游戏，弹窗在小屏上居中可读，并补回桌面端右侧信息栏的查看入口。同时改善首次打开时型号选择突然出现的观感。

## 范围

- 将移动端方向键改为虚拟摇杆。
- 移动端打开商店、图鉴、信息面板或待命型号选择时，不显示摇杆，避免遮挡界面。
- 为移动端新增“信息面板”按钮，用于查看桌面右侧舰桥信息。
- 修复图鉴在移动端横屏下不居中的问题。
- 改善首次加载时型号选择的出现体验。
- 不修改战斗数值、波次、敌人、星舰数据或桌面端右侧 dock 行为。

## 摇杆设计

左下角触控方向区改为一个虚拟摇杆：

- HTML 保留在现有 `.touch-controls` 区域内，减少结构改动。
- 摇杆包含外圈、中心点和可移动摇杆帽。
- `input.js` 根据摇杆偏移设置 `left/right/up/down` 四个移动状态。
- 摇杆归一化半径限制在固定范围内，松手后回中。
- 右下角仍保留慢速和歼灭弹按钮。
- 当 `.modal-layer` 显示或 `.brief` 显示时，移动端隐藏摇杆和动作按钮。

## 移动信息面板

新增一个“信息”按钮，移动端用于打开舰桥信息面板：

- 桌面端仍显示右侧 `.dock`，移动端横屏隐藏 `.dock`。
- 移动端信息面板复用现有 dock 内容的 DOM 或等价结构，避免重新实现星舰、武器、属性和道具渲染逻辑。
- 信息面板作为 modal 或侧滑面板出现，显示星舰型号、武器、属性面板、道具栏和提示。
- 打开信息面板时暂停战斗的逻辑沿用现有 overlay 行为。

## 图鉴适配

图鉴不使用商店的左侧导航布局：

- 横屏移动端图鉴弹窗居中显示。
- 宽度限制为视口内的中等面板，不铺满到贴边。
- tab 横向滚动。
- 图鉴条目在较宽横屏下两列，低高度或窄屏时一列。

## 首次加载体验

当前型号选择并没有定时器延迟；它会在 `main.js` 完成模块加载并调用 `ui.update()` 后立即渲染。移动端感觉延迟的主要原因是首次打开要加载较多 ES Modules。

低风险优化：

- HTML 中保留一个明确的待命加载文案，例如“正在装载舰桥数据...”
- JS 初始化后立即替换为真实型号选择。
- 不引入打包器，也不重构模块拆分。

## 测试

- 为摇杆输入添加单元测试，覆盖拖动、归一化、松手回中和方向键状态。
- 扩展移动端样式测试，覆盖图鉴居中、摇杆样式、信息按钮和控件在弹窗打开时隐藏。
- 为 UI 结构添加测试，确保信息按钮存在并可被绑定。
- 运行 `node --test` 的相关测试和 `npm test`。
- 手动检查 `812x375` 与 `1024x600` 横屏视口。

## 非目标

- 不做竖屏重排。
- 不新增移动端专属战斗规则。
- 不引入构建工具或打包流程。
- 不调整当前未提交的波次数值改动。
